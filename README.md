# AI Process Collector

Capture how a process works through a typed or spoken interview. Review the evidence-linked memo, map and procedure, then save a copy or file a revision in local company knowledge.

**Version 0.31.0** rebuilds **Settings** with a direct header button, six clear sections and a setting finder. Change appearance and voice, edit interview context, manage recovery, check usage, inspect logs, or open the guide without digging through accordions. ## What it does

**Filed processes.** Submit a process to retain a local revision with its transcript, participant attribution and evidence-linked map. A saved interview copy carries the receipt for checking processing status. [Submission storage, matching and revision access](docs/KNOWLEDGE_GRAPH.md)

- Holds turn-based voice conversations without requiring a process title first. Interview questions, notes and completion controls use English. The transcript preserves participant wording. Microphone access starts only when the participant selects Start voice.
- Infers an editable process title from participant answers; a user-selected title wins over later automatic suggestions.
- Accepts reference files during Voice, Transcript or Workflow, acknowledges once and pauses conversation while review finishes. It updates the notes and workflow together before asking one useful follow-up. Select **Continue without waiting** to resume the interview during review. Assets provides purpose, save-for-later and retry actions.
- Offers typed interviews, with optional AI or installed computer playback voices.
- Previews a voice before starting: Marin is the default AI voice, with Cedar as an alternative to compare.
- Dictate an answer to transcribe it and edit the wording before sending. Connected Live voice streams spoken turns, while Reviewed voice transcribes and checks each turn.
- Chooses adaptive follow-ups using the conversation and standing memo framework.
- Captures normal steps, item stages, responsibilities, locations, checks, exceptions and client-specific differences.
- Updates the notes from participant evidence. After each notes update, the background worker can refresh the map regardless of the open tab. Later answers can replace queued work.
- Presents a detailed read-only Report alongside the editable memo, procedure, map, lifecycles, variations and review notes. Report includes the full process context, every captured detail, source evidence and all open questions; returning to it refreshes the latest reviewer edits.
- Uses a locally bundled ELK layout engine for the interactive workflow canvas. Layout positions validated steps and connections; it does not generate process facts.
- Saves the full interview through explicit JSON files; uploaded originals, extracted content and review notes persist locally. Saved JSON carries scoped file references and metadata, not embedded originals. Report and Markdown exports include document sources and reading limitations alongside the complete process and evidence.

This is a single-user local prototype. Teams participation is a later integration step.

## Requirements

- An existing compatible Python 3.12 interpreter with SQLite FTS5 support. The core interview server uses Python's standard library.
- Document parsing uses `pypdf`, `openpyxl` and `Pillow` in the selected Python interpreter. [Supported parser versions](requirements-documents.txt). They must be in that interpreter's own `site-packages`: the app starts Python in isolated mode (`-I`), which ignores packages installed for your user account only. An interpreter without one of them still starts and interviews. Assets then names the kinds of file it cannot read and the missing package and does not upload them, `/api/config` lists them under `documents.unavailable`, and `work/server-lifecycle.jsonl` records a `dependency_missing` event with the module's name. CSV files need no package.
- The interface uses installed Source Sans 3, Source Serif 4 and Montserrat where available. Its fallbacks include Segoe UI and Georgia. No font download is needed.
- A current browser with microphone recording, MediaRecorder and Web Audio support. AI question playback uses WebSockets; installed English computer voices are a local playback choice.
- OpenAI API access for the configured interview and process models. Default live voice uses `gpt-live-1` over WebRTC. Reviewed-turn voice uses transcription and optional AI playback through `gpt-realtime-2.1-mini`.

No runtime, package, browser, model, font or voice is automatically installed or downloaded when the application runs. Reuse your existing approved interpreter. ELK.js is bundled locally with its license and provenance in `web/vendor/`; the workflow canvas does not fetch a layout library from a CDN. This describes `launcher.py` and the `.cmd` shortcuts. The optional [desktop app](#desktop-app-windows) is different: it downloads builds of this application from GitHub and runs one only after you approve it.

## Run locally

Configure `OPENAI_API_KEY` through your secure local environment, or an untracked `.env.local` in this repository. `.env.example` lists the recognized settings with an empty key value. The server never sends the key to the browser. Spaces and line breaks around the key are removed (PowerShell's `Get-Content -Raw` leaves a line break at the end). A key that still contains a space, a line break or a non-ASCII character is not used: the app starts, says so on screen without showing any part of the key, and works again once the key is re-entered and the app restarted. The server's console output and the `start` row of `work/server-lifecycle.jsonl` (`"reason": "provider_key_unusable"`) record the same fact, also without any part of the key.

In live mode, the local server establishes the GPT-Live session and the browser carries the audio over WebRTC. In reviewed-turn mode, the local server sends recorded answers for transcription. For AI playback of an approved question, the browser uses a short-lived token and checks the returned transcript before playing the audio.

In PowerShell, point to an **existing** Python executable and launch:

```powershell
$env:VOICE_INTERVIEWER_PYTHON = 'C:\path\to\existing\python.exe'
& $env:VOICE_INTERVIEWER_PYTHON -I -B .\launcher.py
```

Open `http://127.0.0.1:8774/`. To stop this service:

```powershell
& $env:VOICE_INTERVIEWER_PYTHON -I -B .\launcher.py --stop
```

The Windows `Start Collector.cmd` and `Stop Collector.cmd` shortcuts use the same `VOICE_INTERVIEWER_PYTHON` setting. They do not install an interpreter or change global settings. Use `--port` if the default is occupied; stop with the same port. Runtime logs stay in the ignored `work/` directory inside this repository. The [desktop app](#desktop-app-windows) is installed separately and is not covered by this paragraph.

For a terminal managed by an agent, add `--foreground` and keep its execution session running. This avoids relying on a hidden background child of a short-lived tool job. Ordinary desktop launches retain their existing behavior. Bounded operational events, without transcript or credential data, are recorded in `work/server-lifecycle.jsonl`. The `provider_request_finished` row of each completed Responses request (interview turns, notes, map, draft, file review and knowledge matching) also holds the model name and the input, output, cached and reasoning token counts that the provider reported. These are sizes, not charges: the app keeps no running total, prices or limits, and transcription, AI playback and everything inside a Live voice session are not counted. A response that arrived but could not be used adds a `provider_response_unusable` row whose `error_category` says why (`output_truncated`, `content_filter`, `response_failed`, `refusal` or `invalid_json`), with the same token counts; the person sees a message for that cause.

If the app does not start, the last line of `work/voice-interviewer-server.log` (the console with `--foreground`) names the cause: a busy port, a saved data file that another program holds locked, or data written by a newer build. Only one server can serve a port; a second start on the same port ends with the busy-port line. A damaged `work/documents/documents.sqlite3` or `work/knowledge/knowledge.sqlite3` does not stop the start: the app opens with reference files, or with Submit process, switched off, says so on the page and records a `store_unavailable` row. It never replaces, renames or deletes a damaged file. To begin with an empty store, stop the app and move that file, with any `-wal` and `-shm` files beside it, out of its folder.

Team models use `AGENT_INTERVIEW_MODEL`, `AGENT_COVERAGE_MODEL`, `AGENT_PROCESS_MODEL` and `AGENT_DOCUMENT_MODEL`. `DRAFT_MODEL` optionally overrides the process model for standalone drafts. `INTERVIEW_MODEL` and `WORKFLOW_AUDIT_MODEL` remain for legacy internal functions. `TRANSCRIPTION_MODEL` controls speech recognition; optional `TRANSCRIPTION_KEYWORDS` supplies spelling hints without rewriting the transcript. API usage consumes the configured project's credits or billed usage.

## Desktop app (Windows)

`desktop/` holds an optional WebView2 window for Windows. It is not the launcher above, and the statements above about downloads, global settings and log location do not cover it:

- **It runs a build from GitHub, not your working tree.** The window serves the build of `https://github.com/amelas-dev/ai-process-collector.git` `main` that you last approved, with this checkout's `.env.local` key and the `work/documents` and `work/knowledge` stores. Those stores are the same ones the launcher's server on port 8774 uses: the two share data, each store records its format, and a build refuses data written by a newer build.
- **It downloads, and asks before it runs.** A per-user scheduled task (at sign-in and every 15 minutes) and the window itself download new commits of `main`. A download is only unpacked and checked statically. The window then shows the commit ID, date and subject and asks before switching; until you answer Yes it keeps serving the approved build. Rewritten or older history is refused. If you list trusted signers, unsigned builds are refused as well.
- **It changes things outside the repository.** `desktop/install.ps1` registers the scheduled task **GPFS Process Collector Update**, adds the Start-menu shortcut **GPFS Process Collector.lnk** and tries to pin it to the taskbar. Its files, builds and logs live in the ignored `.local/desktop/` folder. The window uses port 8776.

[Desktop app guide](docs/DESKTOP.md): trust model, trusted signers, prerequisites, everything installation changes, logs, and how to remove it.

## Interview and review

1. Select **Start talking** and allow microphone access when the browser asks. In the default live mode, the microphone streams to GPT-Live and the managed team uses the captions to update the notes. In reviewed-turn mode, each recorded answer goes for transcription after a pause. Wait for **Listening** before answering in that mode: while the interviewer speaks, the microphone is paused and its button reads “Mic paused while I speak”. If you start before **Listening**, the part that was recorded is not used and the page asks you to say it again. You can edit the process title as the interview develops.
2. **Mute mic** pauses microphone transmission. **Stop talking** ends the voice session and releases the microphone. A completeness check that was already running when you stop is not lost: the page shows “Checking the recorded topics and process…” until it finishes, then shows its result. If the notes do not yet include your last spoken answer, the page shows “Updating notes from your last answer…” for a few seconds (ninety at most) before **Create draft**, **Wrap up** and **Continue talking** are available; if that update fails, Notes shows “Notes are behind the transcript” with **Update notes**. Words that Live voice heard while your microphone was measured as silent are not added to the transcript; they are listed under “Speech not captioned” above the conversation so you can say or type them again.
3. Switch to **Transcript** to see the conversation or **Workflow** to see the evolving map. Switching views keeps the same voice connection, transcript, unsent text and capture state; it does not make an API request or restart the interview. Each view scrolls within the workspace. The map and memo refresh together after participant answers or a short pause in captions. Later corrections can revise or remove earlier steps and findings; reported sources are validated, but the model can still misinterpret them.
4. Follow **Notes** beside the conversation, or open **Workspace → Notes** on smaller screens. Select any of the sixteen topics to inspect its evidence. Choose **Type instead** for a typed interview. Before starting, choose **Context** in the top navigation to enter the process owner, goal and background. You can update the owner there during the interview. Once the interview starts, the notes can cite your original goal and background, so give any corrections as an interview answer. Playback preferences are in **Settings → Preferences**.
5. After ending voice, choose **Wrap up** for a final completeness check or **Review draft** for the detailed Report, editable memo, procedure and supporting details. Participant confirmation is separate from owner approval. When the check finds that the sections still open need information you do not have, the interview is kept as a partial capture: Notes says so and names those sections, Live voice ends after the line has been spoken, **Wrap up** is offered again once you add an answer, and choosing it without new information costs no further model calls. When the interviewer asks whether anything is missing, any plain “no” confirms your account (“No, I think that's everything”, “Not that I can think of”), and **Nothing to add** beside “Waiting for your final confirmation.” sends that reply for you. A reply that neither confirms nor adds anything (“Okay”, “What do you mean?”) has the question asked again without a second review, and asking to stop at that point pauses the interview and keeps the review, so **Wrap up** returns to the same question. Once the interviewer has confirmed that the account is complete, a thank-you or a goodbye changes nothing; only something new about the work reopens the review. Updates to the working map never replace edits in Review. Review flags a draft as out of date only after a new participant answer or a change to the active files; **Update draft** rebuilds it and replaces your edits, while **Mark as current** keeps the draft when it already reflects the interview.
6. Save the interview JSON before closing: **More options → Save copy**, or Ctrl+S. Transcript, working map, review draft, title preference and document references are saved together, with a record of the last answer the notes and the working map reached. The full conversation is not automatically persisted: unless you turn on the recovery copy described next, an interview exists only in its open tab, and a reload, a crash, a restart or a forced close loses everything since the last saved copy. While something is unsaved the header says what is known, for example **Unsaved for 40 min · never saved** or **Unsaved changes · last saved 10 min ago**. Uploaded files and their review/index data have separate local persistence, described below.

**Recovery copy (optional, off by default).** **Settings → Data & recovery → Keep a recovery copy on this computer** protects an unsaved interview against a closed tab, a browser or computer crash, a restart or a Windows shutdown. While it is on, the app writes one copy of the unsaved interview to the ignored local `work/recovery/` folder two seconds after a change, and no later than ten seconds after the first change not yet written. The copy is what **Save copy** would write, including your unsent answer; it never holds recordings. It stays on this computer: it is not sent to the AI provider or anywhere else. When the app next opens, a banner offers **Restore** or **Discard**. **Restore** applies the same checks as **Open saved interview…** and leaves the interview marked unsaved. The copy is deleted after a confirmed **Save copy** (a download that cannot be confirmed does not delete it), when you start over or open another interview or the example, when you choose **Discard**, when you turn the option off, and seven days after it was last written. The option and the copy are kept with the app's local data, so the browser and the desktop window share them. Only one interview is kept: while a copy of another interview waits for **Restore** or **Discard**, the interview in the current window is not copied, and the header says **recovery copy paused**. With the option off nothing about an interview is written to disk. The recovery copy is not a saved file: the app still asks before you leave, and a change made in the last seconds before a crash, or after the local server has stopped, can still be lost.

Set `VOICE_MODE=reviewed` to use recorded turns, transcription and verified question playback. In that mode a pause of 1.8 seconds ends your turn (`VOICE_PAUSE_MS` changes it, 1000–5000 milliseconds); the page then shows “Thinking… keep talking if you weren’t finished”, and anything you add before the reply is spoken joins the same answer. In reviewed-turn mode, recordings sent for transcription include sound from when listening starts, including the lead-in before speech. In voice settings, choose **Edit each reviewed-voice answer before sending** to put the transcription in the reply box. Without that option, reviewed voice adds recognized answers automatically. End voice before opening **Review**. You can save the transcript if the provider becomes unavailable.

**Live voice context limits.** A new GPT-Live session can reload at most 128 earlier turns and 7,800 bytes of transcript text, roughly ten minutes of dialogue. A longer conversation can still start or resume voice, for example after a file upload, **Stop talking**, a lost connection or reopening a saved interview. The new session is then seeded with a condensed history: the current notes summary, the topics that are still open or only partly covered, and the most recent whole turns that fit. The most recent answer has priority: the summary is shortened to make room for it, and only an answer that is itself longer than the limit is seeded as its end, marked as such. The app says so beside **Continue talking** before you select it, again when voice has resumed, and beside the voice controls for as long as that session is on. Notes, the workflow and the report still use the full transcript. The session's instructions are limited to 32,000 characters in total. When the retrieved file context does not fit beside the interviewing rules and your intake details, voice receives a digest of it (each file's summary, review state and limitations, then observations and the highest-ranked exact excerpts: sources your notes already cite, then the excerpts that best match the latest turns of the conversation) that is marked as a selection, and the app tells you, for as long as that session is on, that voice is using a shorter selection of your files. These limits are the application's own conservative bounds; they have not yet been confirmed against the voice service with a long interview or a large file.

**Interview length.** One interview holds at most 400 turns (questions and answers together) and 400,000 characters. From 360 turns, or 350,000 characters, a line above the conversation says how much room is left and suggests wrapping up. New answers stop at 392 turns, and Live voice ends there without dropping the words that reached the limit, so that the closing sequence still fits: **Wrap up** stays available until the acknowledgement, the final-check question, your reply and the closing line no longer fit, and your reply to the final check is still accepted. **Create draft** and **Save copy** remain available throughout.

Select **Invoice approval** on the welcome screen to explore a fictional process. To load the bundled `Examples/Synthetic-reviewed-session.json` file, use **More options → Open saved interview…**. Opening either example requires no model call.

Use **Transcript** for the conversation. **Review** contains Report, Notes, Workflow, Steps, Items, Variations and Open questions. Use the arrow keys, Home or End to move between review tabs. The SVG download includes the full workflow at any zoom level.

## Reference files during the conversation

The interview workspace has three tabs: **Notes** for topic coverage, **Summary + Parked** for the running summary and topics to revisit, and **Assets** for uploaded files. On smaller screens, select **Workspace** to open these tabs.

Select **Assets → Add files**, or drop files anywhere in the interview. Uploads are available without a process name and during a voice session. The app acknowledges the upload once, stops live voice and turns the microphone off while it digests the files. Assets is the central file list, with progress and recovery actions on each card. Expand **Review details & sources** for relevance, indexing coverage, reading limits, exact sources and questions.

The progress panel moves through upload, review, process update and follow-up. Initial relevance findings remain in Assets while the active files finish reviewing. After final captions and review settle, the app audits and commits the notes and workflow together, then asks one question grounded in that accepted baseline and the exact sources. A finished review can still have limited coverage; those limitations stay visible. New uploads or file changes cancel obsolete results. Select **Continue talking** to resume voice using the current file scope at startup, without a second stream of file updates. After a long conversation, voice resumes with a condensed history, as described under **Live voice context limits**.

If a file fails, use **Retry review**, remove it or choose **Save for later** in Assets. The card says what kind of problem paused the review (rate limit, quota, rejected key, timeout, network) where the app knows it. A rate limit, timeout or provider-side error is tried again twice before the review pauses, and **Retry review** then continues where the review stopped instead of sending the sections already reviewed again. A page or image the reviewer cannot read is listed under **Reading limits** and the rest of the file is still reviewed; **Read again** sends only those pages or images once more. A failed baseline update retains the last accepted capture; a failed follow-up retains the newly accepted baseline. **Continue without waiting** lets you leave an error with the current capture intact. If the file's purpose is unclear, provide it in Assets. When the reviewer does not find a file related, the card shows its verdict and reason: **Use this file anyway** puts the file to use as your own choice, and **Revisit this file** reviews it again and lets you word the purpose differently. While a review runs, the card shows about how many more requests it will send, and **Stop review** ends it without removing the file: the file stays searchable and readable by the interview, and **Continue review** resumes it. Parked files retain their analysis and **Questions for later** for an explicit **Discuss** action. Document claims remain documented reference material until the participant establishes current practice; an upload does not confirm completeness or owner approval.

The tray opens the exact cited PDF page or spreadsheet sheet/cell text for review. It displays incomplete visual extraction, unsupported material, formula limitations and review failures. PNGs and PDF pages without extractable text require AI visual review; visual transcriptions remain unverified, and each such excerpt says so where it is read: the source preview in Assets, the source dialog opened from a citation, the citation's caption and the **Cited document excerpts** of the report export carry “AI visual transcription is unverified; inspect the original before relying on it.” Workbook formulas and saved cached values are indexed as text/data, never recalculated. XLSM macros, external links and embedded actions are never executed. Chart-only sheets remain explicit gaps when their contents have not been reviewed.

After an update that changes how files are read, a file indexed by the earlier version is first read again on this computer when you open the interview (**Checking after update**). This sends nothing to the AI provider. If the current version reads the same sections, the file is current again and keeps its review; whether that review counts as complete is decided from what the current version counts as read. If it reads the file differently, the file shows **Needs re-indexing** until you choose **Re-index and review**, and the interview cannot be completed until then or until the file is saved for later or removed. That action re-indexes the saved original and sends it to the AI provider for a new review, which uses provider credits; pages and images that need visual reading are sent again. A stored AI visual transcription is kept unless its new reading succeeds, so a retry that fails leaves the stored text, and the notes and connections that cite it, as they were. A successful new reading supplies the text for future searches and citations. The Assets panel explains this before you start.

For spreadsheets, local extraction indexes populated rows across every accepted worksheet into SQLite FTS5, with sheet/cell references. It does not stop at a header preview or the first 1,000 rows. OpenAI's native Responses `input_file` spreadsheet augmentation uses up to the first 1,000 rows per sheet; this app's local corpus extraction is separate from that smaller model view. [Official OpenAI file-input documentation](https://developers.openai.com/api/docs/guides/file-inputs#how-spreadsheet-augmentation-works). Indexing all accepted source rows makes them searchable; it does not mean the model has already reviewed or understood every row. Initial relevance uses selected content; the background review then works through the whole extracted text in bounded batches, with explicit progress.

Supported limits are **64 MiB per file** and **20 files per local interview scope, including archived originals**. Removed files, and files that failed to upload cleanly or could not be read, keep their slot: Assets shows the count ("7 of 20 file slots used, 3 by removed files") and turns **Add files** off, with the reason, when every slot is used. A removed file can be restored from **Removed files**; a slot cannot be freed. PDFs accept up to 500 pages; workbooks up to 100 sheets and two million populated cells, with at most 1,048,576 rows per sheet. PNGs must be within forty million pixels. The extracted text corpus is bounded to 64 MiB and 50,000 chunks. Files outside supported bounds fail visibly instead of publishing a silently truncated index. Legacy `.xls` is not offered in the upload picker; convert it to `.xlsx` or `.csv`. The parser's optional legacy-XLS path requires `xlrd`, which is not included in the pinned requirements.

Originals, extracted content, the SQLite index, source metadata and review notes are stored in the ignored local `work/documents/` directory. A file record retains where the file was supplied: the process name, the objective, the question it was added under and the ID of the participant's turn before it. It does not copy what the participant said (records written by version 0.29.0 and earlier also hold up to four recent turns). **Start over** resets the conversation's file references without deleting originals. **Remove from interview** detaches/archives a file from that interview; it is not a permanent file purge. Assets says so on the button, in the file notice and when you start over.

**Erasing uploaded files.** Nothing in the app deletes an uploaded file, its extracted text or its review notes. To erase them, close the app (and the desktop window, if you use it) and delete the folder `work/documents`. This erases the files of every interview on this computer; there is no supported way to erase one file or one interview's files. Saved interviews still open afterwards and list their files as saved references that are no longer available. Processes already submitted to Company knowledge keep the excerpts their notes cite in `work/knowledge/knowledge.sqlite3`; deleting `work/knowledge` as well erases those together with all Company knowledge. Deleting a file this way does not overwrite the disk space it used.

A quick read sends the file name and initial extracted evidence to OpenAI. A full review can send every indexed row and sheet, including hidden sheets, plus a PNG or individual PDF page for visual reading. A large review can pause after the sample; unrelated files also await your choice. **Continue review** resumes a paused sweep. **Save for later**, **Stop review** or **Remove** stops further review. A request already in flight may finish. Review limits and the sections actually read appear in Assets. Later interview requests include selected passages from active files and only previously cited excerpts from parked or removed files.

Assets lists removed files under **Removed files**. **Restore** puts a file back as it was without reviewing it again. Notes and steps that cited a removed or saved-for-later file keep the passage as a saved excerpt, and **Submit process** files it that way, flagged for the reviewer. The Submit dialog names those files before you submit and offers to leave their passages out. A new process cannot rest on a saved excerpt alone, and a revision can only where an earlier revision already holds the passage: the Submit dialog then names the file and the steps or notes involved, and offers **Submit without these citations**.

Save the interview JSON to retain the links back to these files. Reopening it on the same computer can restore those references and verify current file status. The JSON contains metadata and scoped references, not original binaries: moving the JSON alone to another computer does not transfer the documents. Back up or relocate `work/documents/` together with the JSON when preserving the complete local workspace. If a referenced local file workspace cannot be reached, the saved metadata remains visible with an explicit error.

## Data and review boundaries

Submitted interview text and recorded audio are sent to OpenAI. So are uploaded files: their names, their full extracted text and any page or image that needs visual review, as described under [reference files](#reference-files-during-the-conversation). Connected live voice continuously sends microphone audio to GPT-Live 1 until muted or ended. Optional question playback also sends question text to OpenAI for AI-generated speech through `gpt-realtime-2.1-mini`; installed computer voices play locally. Generated playback audio is held in memory rather than saved by the application. Developer content tracing, when enabled for this workspace, writes committed interview wording, model exchanges and application events to private local JSONL files as the interview runs. The optional [recovery copy](#interview-and-review) keeps a separate restorable interview in `work/recovery/`. Audio stays outside both stores. [Developer event trace modes and reader](docs/RAW_EVENT_TRACE.md). Uploaded files, extracted content, their review notes and bounded intake context persist locally; save the full interview JSON explicitly to retain the complete conversation and its file references. `store:false` is used for model response requests and does not replace provider account policies.

Natural AI playback reads the displayed question rather than generating the interview's next question. Before playback, the client compares the returned speech transcript with the requested text, ignoring case and punctuation, and withholds audio on a mismatch. This check can also reject equivalent spoken forms, such as expanded numbers. Stop, a voice change or starting a recording cancels pending playback.

The service binds only to `127.0.0.1`, checks Host/Origin/CSRF values and serves an explicit asset/API allowlist. It is not a shared production service. Review access, retention, deployment and microphone behavior before use with real business information.

Submitting a process stores a local revision and can send bounded evidence from that revision and up to eight related stored submissions to OpenAI for matching. Any process running as a trusted local user and able to reach this listener can request its token. Keep this prototype on a trusted single-user computer. [Stored copies and deletion](docs/DATA_HANDLING.md)

The tool cannot guarantee that every relevant fact has been elicited or interpreted correctly. Source IDs establish attribution, not semantic truth. Unknown actors, locations, timing, handoffs and exception paths must remain visible until a knowledgeable reviewer resolves them.

## Offline tests

```powershell
& $env:VOICE_INTERVIEWER_PYTHON -I -B -m unittest discover -s tests -v
```

The desktop app tests (`tests/test_desktop_*.py`, and the desktop part of `tests/test_store_format.py`) run on Windows only and need `git` on `PATH`. They build throwaway repositories under the ignored `.local/` folder, which they create if it is missing, and use no network. The check that compiles `desktop/NativeHost.cs`, the check that parses the two installer scripts and the signed-build test are skipped when the .NET Framework compiler with the WebView2 SDK, PowerShell or `ssh-keygen` is not on the computer.

With an existing Node installation, run every frontend suite with one command:

```powershell
& 'C:\path\to\existing\node.exe' .\tests\run_all.cjs
```

The runner lists `tests/*.cjs`, so a new suite is included without being registered. It runs each suite in its own process, prints one `PASS` or `FAIL` line per suite and exits non-zero if any suite fails. It needs no package manifest or dependency. Add `--list` to see the suites without running them. A single suite still runs directly, for example `& 'C:\path\to\existing\node.exe' .\tests\test_ui_state.cjs`.

### Browser and typography

The desktop window uses Microsoft Edge WebView2. Current Edge and Chrome are the tested standalone browsers. Other browsers may show a simpler layout or offer fewer voice controls. The interface uses locally available Source Sans 3, Source Serif 4 and Montserrat, with Segoe UI and Georgia as fallbacks. No font download is required.
