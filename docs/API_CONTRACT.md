# Local HTTP interface

The browser uses a loopback HTTP service. GET `/api/config` returns capabilities, model aliases, build identity, available document types, local storage health and a per-server CSRF token. All POST routes require the current `X-CSRF-Token`, the matching localhost Host and a permitted Origin when present. State-changing requests require an explicit Content-Length. The anonymous `X-Interview-Id` header says which interview a request belongs to, so that its file workspace and background work are attributed to it. In `/api/config`, `request_timeouts_ms` gives how long the page waits for each kind of request, `live.caption_check` says whether live captions are checked (`LIVE_CAPTION_CHECK`), and `agent_team.stop_intent_patterns`, `stop_named_intent_patterns` and `stop_sign_off_pattern` let the page read a request to stop as the server does. The `documents.pdf_reader_version` field reports the effective PDF reader version, or `null` when PDF reading is unavailable.

The interview snapshot contains `context` and `turns`. A turn carries a unique ID, role and text. A capture token, conversation token, review ticket, file scope or submission-status receipt is opaque. Keep it with its own interview. The service resolves source text from the local store and validates citations. A browser-supplied source label cannot grant access.

An interview request can include `file_topic_reviews` with one decision per topic. Each entry contains `topic` and `decision` (`confirmed` or `needs_changes`). A confirmation requires the exact `answer` reviewed and adds it to participant context. A flag asks the interviewer to clarify the file notes when material. The interview still checks coverage and waits for its own final reply. Saved interviews keep both the reviewed `answer` and the original `source_ids` for each decision.

| Method and path | Caller, input and result |
| --- | --- |
| POST `/api/conversation/turn` | The interview sends a snapshot and action. A client can supply a random 64-character lowercase hex `conversation_start_id` on its first turn and retain it across retries until it receives the conversation token. Returns the immediate question or pause, a conversation token and capture progress. |
| POST `/api/conversation/cancel` | End the conversation identified by `conversation_token` and cancel its queued work. A same-interview mode switch sends `handoff: true` to retain a review issued for the same evidence. Repeated cancellation is safe. |
| POST `/api/conversation/discard` | Stop queued analysis using the conversation token and pause file review using the document scope. Repeating a successful request is safe. |
| POST `/api/conversation/status` | Poll the current conversation. Returns progress and available notes/map results for that revision. `workflow_state` and `workflow_pending` describe the map of this revision as drawn. When it is there, `workflow_capture` carries it (with `generated_by` and `app_version`, the latest draw and the latest check) with `workflow_checked` (whether the map source-review stage finished), `workflow_version` (changes whenever the map does) and, until that stage finishes, `workflow_check_state` (`working` or `error`) with `workflow_check_error` for a failure. Until it is there, `workflow_checkpoint` can carry the map through an earlier answer: `revision`, `through_turn_id`, `turns`, `workflow_capture`, `checked` and `version`. Apply it only while its turns are still the beginning of the conversation. |
| POST `/api/conversation/sync` | Reconcile the current conversation and its background work after new evidence or reconnection. Returns the synchronized notes with the map's own state; a map that is returned carries `workflow_checked`, `workflow_version` and, while unchecked, `workflow_check_state` as above. |
| POST `/api/agent-team/interview` | The capture worker submits a snapshot for the coordinated lead. Returns the evidence-linked memo and capture state. Live voice notes an answer that is still being spoken with `live_notes: true`, `action` `answer` and `live_partial: true` (also on `/api/interview`): such notes are for display only, carry `live_partial: true`, issue no capture token and are never continued from. `live_partial` other than `true` or `false`, or on any other request, returns 400; words that read as a request to stop, or as a reply the held capture answers, return 409 until the answer has ended. |
| POST `/api/agent-team/workflow` | Submit the snapshot and an optional accepted previous capture. Returns the updated map, open questions and source references. In Live voice without files the page may add `draw_first: true`: the map is then returned as drawn, before its source check, with a `check_token`; the same snapshot sent again with that `check_token` returns the checked map. The token is single-use, kept for ten minutes and valid only for the snapshot the map was drawn from. A request that is not such a live map is answered in one piece without a token. `agent_team.live_map_draw_first` in `/api/config` says that the server offers this. |
| POST `/api/agent-team/review` | Submit the issued review ticket and matching evidence. Returns the completion assessment, blockers and speech authorization. |
| POST `/api/agent-team/coverage` | Request provisional checks of captured topics in a current capture. Returns topic-level results and their answer bindings. |
| POST `/api/agent-team/status` | Look up the current agent run and its role progress. |
| POST `/api/agent-team/cancel` | Cancel the specified run. Obsolete results cannot replace the current capture. |
| POST `/api/interview` | Compatibility interview entry point. The built-in client uses the coordinator. |
| POST `/api/workflow` | Compatibility map entry point. Accepts the interview snapshot and optional previous capture. |
| POST `/api/draft` | Generate and independently check a draft against participant and document evidence. Returns the draft and available coverage or file evidence. |
| POST `/api/transcribe` | Send supported audio bytes with their media type. Returns transcription text. The body limit is 12 MiB. Optional `X-Transcription-Hints` lists terms the interview has used (comma-separated, URL-encoded; an unreadable list means no hints). The live caption check sends `X-Transcription-Purpose: live-caption-check`: its hints are then only the fund terms, the process name (its first hint) and `TRANSCRIPTION_KEYWORDS`, and the result also carries `terms`, the terms the check may write into the caption, and `misheard`, their listed misheard forms. That header returns 400 unless `LIVE_CAPTION_CHECK` is on, and so does any other value. A recording the service cannot decode returns 422. |
| POST `/api/voice-session` | Request a short-lived reader credential for the selected voice. |
| POST `/api/live-session` | Submit WebRTC SDP and interview snapshot for connected Live mode. Returns SDP and session metadata. |
| POST `/api/documents/session` | Establish or reopen a private document scope for interview intake. |
| POST `/api/documents/upload` | Send raw file bytes with the file scope and encoded name in the request headers. Returns an accepted document and starts indexing. Maximum 64 MiB per file. |
| POST `/api/documents/status` | List the scope's current records, progress, limitations and available actions. |
| POST `/api/documents/action` | Apply a file-specific action using its scope, ID and current state. Returns the updated record. |
| POST `/api/documents/source` | Open the authorized, indexed source location belonging to a file in this scope. |
| POST `/api/documents/withdraw-confirmation` | Withdraw one immutable confirmation reference in its authenticated document scope. Repeating the request is safe. |
| POST `/api/documents/context` | Retrieve the bounded selection for an interview scope, query and optional preferred source IDs. Returns authorized excerpts, evidence catalog and reading limits. |
| POST `/api/knowledge/submit` | File a bounded snapshot as a new process or authorized revision. Returns HTTP 202 with the filed revision number and private status receipt. |
| POST `/api/knowledge/status` | Read the status associated with a valid submission, revision and receipt. |
| POST `/api/shutdown` | Local launcher requests orderly shutdown. The launcher verifies checkout and running process identity. |

Clients can send a 32-character lowercase hex `operation_id` to `/api/conversation/turn` and `/api/conversation/sync`. Reuse it when retrying the same snapshot and action after a lost response. Concurrent duplicates share one execution. Reusing the ID with a different action or transcript returns 409.

Successful operations normally return JSON with HTTP 200. Upload acceptance returns 202. Invalid shapes, stale state, unavailable services and oversized uploads return distinct errors. Common statuses include 400 for invalid inputs (an empty body included), 403 for rejected authorization, 404 for missing items, 409 for conflicting state, 413 for size, 415 for media type, 422 for a recording that cannot be decoded, 429 for local/provider limits and 503 for unavailable stores. A request to the AI service waits up to 8 seconds for one of the four places for such requests before it returns 429; a draft head start (`prepare_only`) takes a free place or none. Unexpected server failures return a correlation ID where available.

Local-owner mode or a trusted server-side authorizer controls revision access. A saved receipt permits a status lookup for its specific filed revision. The typed concurrent, document-analysis and agent-team flows depend on the built-in provider integration. A hosted adapter must implement and test the corresponding capabilities. ## Source authority and review results

A Workspace confirmation carries an immutable reference beginning with `review_v1_`, the topic and exact confirmed answer, the original excerpt IDs in `source_ids` and the revision of each excerpt in `source_revisions`. Only the scoped document store can resolve that binding. A changed or unavailable source requires a fresh decision. Decisions from older files without a resolvable binding remain historical. A participant can still give independent testimony in the transcript.

Send `file_review_withdrawals` with the next interview snapshot to synchronize any offline withdrawals. The status endpoint accepts `confirmation_references` for a reopened file and returns the matching `withdrawn_confirmations` list. A scoped decision remains withdrawn after reopening or restarting the app. Older in-flight work can return a 409 if its source authority has changed.

Working-map responses carry `route_assurance` alongside the workflow. Drafts carry the same list within the draft. Each route names its endpoints, condition, evidence IDs, review status and revision. A supported route also includes the verified source passages. A missing receipt means the source check is unknown. Pending and unread routes can appear on a current map. Review the route details and open owner questions before using it as a procedure. Draft sections flag material entries with unresolved evidence in the entry itself. A filing receipt identifies a stored revision. Formal process-owner approval takes place separately.

Live session creation reports `file_access`. The first start also returns the matching `opening` instruction. A resumed conversation skips the greeting. The access values are `none`, `unread`, `summary` and `excerpts`. They describe the content included in that session. Prepared drafts share a compatible writer across requests. Material changes invalidate the candidate. Create Draft still performs the independent source audit.

Completed filing status can include `matching_coverage` with the counts of eligible processes, candidates compared and proposals retained. Older jobs may lack these counts.
