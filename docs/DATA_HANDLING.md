# Where interview data goes

Process Collector runs under the signed-in Windows account. Local permissions and backups determine who else can read its files. The listener binds to 127.0.0.1. Host, Origin and the request token protect the browser from cross-site requests. Other programs with access to the listener can read its configuration and token.

| Copy | Contents and location | Retention and removal |
| --- | --- | --- |
| Open interview | Browser memory holds turns, edits, map, draft and the current answer. Playback and retryable audio are held in memory. | Save a copy before closing if you need to reopen. Closing the page ends the in-memory copy. |
| Optional recovery | Settings can keep one unsaved interview, including an unsent answer, in the private work/recovery folder. Audio is excluded. | Off by default. The saved recovery is cleared by discarding it, switching the option off, starting over, opening another interview, confirming a successful save or reaching the seven-day expiry at cleanup. |
| Save copy and exports | The browser downloads a file to the location chosen by the user. The restorable copy includes file-workspace capabilities. Markdown and transcript exports are intended for review. | Delete downloaded files and any copies sent to reviewers separately. A restored file workspace requires its matching local store. |
| Document workspace | Originals, indexes, extracted passages, model observations and bounded recent intake context live in work/documents. | Save for later parks the file. Remove takes it out of active review. Previously cited excerpts and historical revision evidence may still exist. Removing a card or closing the window does not purge the underlying store. |
| Submitted processes | Submitting explicitly files an immutable revision in work/knowledge/knowledge.sqlite3. Later revisions are added to its history. Links, review decisions and source evidence can persist with the revision. | Filed revisions persist after Start over or closing the app. The interview has no per-submission erase control. Shared documents, exported files, other submissions, backups and provider copies have separate lifecycles. |
| Local diagnostics and token totals | Rotating work/server-lifecycle logs hold operation metadata such as stage, duration and failure category. work/provider-usage.sqlite3 stores UTC dates, anonymous interview labels and token counts. | Server logs rotate on size. Remove local copies only with the app stopped. |
| Application logs | The selected mode controls the JSONL in `work/raw-trace`. Content mode records committed interview wording, model exchanges, and changes as the app observes them. View entries and logging information in **Settings → Application logs**. Metadata mode keeps operational fields and omission markers. | Files survive closing the interview, starting over and removing the local submission store. A file can cover several interviews. Close the app before removing a run’s local files. Independent downloads and backups have separate lifecycles. See [Event trace modes and reader](RAW_EVENT_TRACE.md). |
| OpenAI requests | Typed and transcribed turns, intake fields, review-ready documents and images can be sent to the configured project. Company knowledge matching can send bounded excerpts from the filed revision and up to eight eligible stored submissions. Live voice transmits microphone audio until muted or stopped. It also sends the audio of each finished answer again, to the transcription model, to correct fund terms and configured names in its caption; `LIVE_CAPTION_CHECK=off` stops this, and speech while muted is never sent. Reviewed voice sends recordings for transcription. AI playback sends question text. Installed computer voices play locally. | The app can stop future requests. Local deletion cannot remove provider-side records. Responses model requests use store=false. Provider account and service settings govern retention outside this app. |

To remove an entire local workspace, stop every instance using it and identify the intended data directory. Back up any records the owner wants to keep. The work/documents and work/knowledge directories are shared across interviews. Deleting either directory removes data for multiple interviews. A copied backup, a download, an installed build and an already shared export each require separate attention. The source repository excludes the private stores, environment file and diagnostics.


Start over waits for the local server to discard the conversation and pause further file review. Closing a browser tab requests the same cleanup when the browser delivers its page-close event. A browser crash or a request already sent to the provider can outlast the tab. Indexed files stay in the workspace and can be reopened from a saved copy. When two tabs share a file workspace, pausing its review applies in both tabs.
