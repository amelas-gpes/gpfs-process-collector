# Demonstration and recovery guide

Use fictional information. Before replacing an open interview, choose **Menu → Save copy** (or press Ctrl+S). Recorded answers remain in the page; save a copy to retain them independently. Nothing else keeps an interview.

## A short walkthrough

1. **Welcome → Invoice approval.** Open the example workflow and point out **Example · Everything here is fictional**. The example is also available under **Menu → See an example**.
2. **Interview → Transcript.** Read an answer and follow-up; use **Find**. Open a topic in **Workspace → Notes** to show its answer, topic guidance and sources. On a narrow screen, open **Workspace** first.
3. **Workflow → a step → a source.** Select a diagram step, follow its reported next step, and open a cited answer. **Back to step** returns to that citation. Use the step selector or **Follow path** to explore a handoff. **Map tools** contains zoom, **Fit entire map**, orientation, and the diagram key.
4. **Review.** Open the example with **Open draft**. Explore **Report**, **Notes**, **Workflow** and **Open questions**; point out **Needs owner review**. In a real interview, **Create draft** becomes available in Workspace and Review after an answer or file provides source material. **Update draft** replaces manual edits after confirmation.
5. **Save and export.** **Save copy** writes the restorable interview. Where the browser offers a system Save dialog (Chrome and Edge), choose a location; **Saved** appears only after the file is written. Otherwise a download starts and the header shows **Last copy downloaded** with the time. **Transcript → Export** offers Markdown or JSON. In Review, use **Download report** for Markdown, **Download notes** for the memo, or **Workflow → Map tools → Download map (SVG)**.
6. **Optional live segment.** Choose **Start your own → Type instead** for a fictional exchange. Use **Start talking** after the device checks below. Stop when useful; do not invent details to reach completion.

## Explain what the team and topic states mean

There is one interviewer voice. GPT-Live leads the default voice conversation. The **Lead interviewer** maintains the account and handles managed turns; **Coverage reviewer** and **Process reviewer** inspect completion readiness. **Document analyst** handles supplied material. The team status sits beside the Workspace title once a role has run; select it for the roles. **Standing by** is normal when a role is not needed. **Done** means work finished, not necessarily that the account passed.

**Unknown** and **In progress** mean the section still has gaps. **Captured** (before the final check) is provisional; **Needs detail** marks a topic that was discussed but is not yet clear. A topic is officially covered only when its explanation and required details have evidence, with no unresolved assumptions. An unavailable answer remains open; a partial draft can still be useful. Participant confirmation and process-owner approval are separate.

When the candidate account is ready, one acknowledgement precedes the completion review; the app tracks the approved line and offers text recovery if delivery fails. Review can produce another question, a final omissions check, or a partial handoff. Confirmation cannot fill missing sections. Retrying the same failed review does not repeat its acknowledgement. **Wrap up** remains unavailable until its prerequisites are met.

## Recover without losing the account

| Situation | Action |
|---|---|
| Typed completion review is taking too long | **Pause review** preserves recorded answers and unsent text. **Resume review** starts with fresh review authority; paused results cannot close the account later. |
| Voice needs to stop | **Stop talking** ends capture and playback. **Mute mic** is temporary. Use **Type instead** to continue. |
| An interview or completion request fails | Use the displayed **Try again** or **Retry completion review**. Do not resend the same answer as a new message. |
| A file needs attention | In **Assets**, use **Retry upload**, **Retry review**, **Retry source** or **Retry action**, as offered. **Continue without waiting** returns to the interview with file work unresolved. |
| A file needs a purpose or is for later | Enter what to look for and choose **Review now**, or **Save for later**. **Revisit this file** brings a parked file back for review. |
| Facts or sources change | Add the correction and inspect its source. Adding, removing or revisiting files changes the evidence basis. Continue interviewing or use **Recheck coverage** when offered. Earlier completion does not apply automatically. An **Initial overview** preserves earlier reading; current review counts and limitations are shown separately. |
| The tab, the browser or the computer closed with unsaved work | The unsaved work is gone: an interview exists only in its open tab until a copy is saved. The header cue, for example **Unsaved for 40 min · never saved**, is the reminder to save. |
| A copy may not have been written | Cancelling the system Save dialog leaves **Unsaved changes** in place and saves nothing. A download is reported as **Download started**, never as saved, because it can be cancelled or blocked: check the file in your Downloads folder. Until a save is confirmed, the app keeps asking before the interview is replaced or the tab or window is closed. |
| Reopening saved work | **Menu → Open saved interview…** accepts a Save copy file. Answers and sources remain, but previous coverage/closure is provisional until rechecked. Opening alone does not request a model response. |

## Hands-on device check before a voice demonstration

These physical checks remain to be performed on the presentation device:

- [ ] In **Settings**, choose the intended playback voice. In a typed interview, select **Listen** on a question to hear it; confirm the actual headset/speaker route, intelligibility and volume, and that **Stop** ends it.
- [ ] Start talking, wait for **Listening**, and speak a short fictional answer. Confirm the transcript, the next question and natural pause handling.
- [ ] Check **Mute mic → Unmute mic**, then **Stop talking** during playback. Confirm no further sound or capture and that typing remains usable.
- [ ] Check that the interviewer does not capture its own speaker output in the intended room/device arrangement.
- [ ] Verify microphone-denied recovery to typing and **Save copy → Open saved interview…** with a disposable fictional session.

The November 2026 checks used real Chrome for the UI, controlled fictional responses for broad recovery scenarios, and actual voice/transcription services for a synthetic-audio roundtrip. Native browser playback and recording were exercised; Chrome output was muted and no physical microphone was used. Those results do not establish physical audio quality, live process accuracy, final release readiness or a latency guarantee.
