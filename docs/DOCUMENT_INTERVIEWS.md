# Interviews with existing documents

Drop one or more supported files onto the interview workspace, or use **Assets → Add files**. The Assets tab is the central place to track uploads, manage files, and read their details and sources. On smaller screens, open **Workspace → Assets**. Both upload methods share the same file limits, progress display and error recovery. Text dragging remains normal; dropping a file outside the upload workspace does not navigate away from an interview.

An accepted upload receives one acknowledgment: the interviewer asks for a moment to digest it. Live voice stops, releases the microphone and waits for final captions. The progress panel shows upload, review, process update and follow-up; initial extraction and quick-review findings do not start competing questions or replace the working diagram.

Once the active files finish reviewing, the app uses the documented name, sequence, roles, branches and controls to build the next baseline. Notes and workflow are audited and committed together before the interviewer asks one useful question about a real gap, contradiction or currentness issue. The follow-up uses that accepted baseline and exact sources rather than asking the participant to retell the file. If no useful answerable gap remains, it can offer a recap or pause. A source may itself identify unresolved assignments; these remain open.

The post-upload question receives a separate source-first audit using the configured `WORKFLOW_AUDIT_MODEL` (default `gpt-5.4`). A gap in an AI-generated summary cannot override an answer in the original source. For example, a documented next step and owner can be known while the way they receive a handoff remains unclear. Ordinary interview questions retain their normal model.

Select **Continue talking** when ready to resume. The new voice session receives the current file scope at startup for server-authorized source retrieval; files are not appended again as incremental voice updates. The microphone stays off until the participant resumes voice or dictation.

Documentary evidence is distinct from participant confirmation. Notes display **Documented**, with source excerpts available from each citation. The document alone does not establish current practice, exhaustive completeness or owner approval. Current operating steps remain separate from proposed improvements and separate regional processes. Saved interviews retain the cited excerpts; procedure exports include their provenance. Transcript exports list documentary references without embedding the files or their text.

Before a document-based map is accepted, a separate audit checks its proposed edits against the same source excerpts and the process boundary. It checks regional applicability, required signoffs, exception routes, unsupported connections and proposed changes. The source audit uses `gpt-5.4` by default, configurable with `WORKFLOW_AUDIT_MODEL`; the normal interview retains its separately configured model. This additional review takes longer than transcript-only capture; the app shows its progress and retains the last accepted notes and diagram if generation or audit fails. A follow-up failure leaves the newly accepted baseline intact.

Exact sources are retrieved from the current interview's private file scope. Browser-supplied citations cannot authorize new facts. Requests retain prior cited excerpts within a bounded context: up to 60,000 source characters, 120 chunks and six active files. Large or partially readable files disclose omissions and reading limitations. Review phase `complete` means processing has finished; `review_complete=false` can still disclose limited coverage. Voice startup uses a smaller selection of exact excerpts and discloses that selection. Original files and private scopes remain local and outside Git.

An active file with an extraction or review error blocks the new baseline and question. Use Assets to retry, remove it or save it for later. On error, **Continue without waiting** resumes with the current capture. Empty or entirely parked uploads leave existing notes and workflow unchanged and do not manufacture a question from older files.

If the file review finishes but the process update times out, use **Try again** in the review panel. The uploaded file and completed review are retained; re-uploading is unnecessary. Document workflow generation uses a 120-second socket timeout and its independent source audit uses 240 seconds; the browser allows seven minutes overall. A timeout is reported separately from connection, DNS, or secure-connection failures. Status polling does not retry a failed update or follow-up; explicit retry or a change to the active files can resume it. Local operational diagnostics identify the stage and duration without storing document text, interview content, credentials, or raw provider error messages.

Changing a file's purpose, parking/removing it, or opening another interview invalidates late responses based on its prior state. Prior cited facts survive file removal as saved evidence; removed or parked material cannot silently authorize new workflow claims. Explicit step/route deletions still require a participant correction.

Knowledge submissions resolve documentary citations again on the server and preserve their source type and exact text for review. They do not convert file text into participant testimony or approval.

See [build verification](BUILD_VERIFICATION.md) for executed checks and remaining limits; the behavior described here is not a claim of physical microphone or speaker verification.
